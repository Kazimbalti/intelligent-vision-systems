Everything here is a pixel-wise operation: the output at \((x,y)\) depends only on the input at \((x,y)\) (plus, for adaptive methods, a small local neighbourhood). No spatial mixing yet — that is next lecture.

Point Operations, Defined

A point operation (a.k.a. intensity transformation) applies a function \(T\) independently to every pixel:

\[ g(x,y) = T\big(f(x,y)\big) \]

  • \(f\) = input image, \(g\) = output image, \(T\) = the transfer function / mapping
  • For an 8-bit image, \(T\) is fully described by a table of 256 output values — a look-up table (LUT)
  • Building the LUT once and indexing into it is dramatically faster than evaluating \(T\) at every pixel
import numpy as np, cv2

lut = np.array([T(i) for i in range(256)], dtype=np.uint8)
out = cv2.LUT(img, lut)          # vectorised, O(1) per pixel after the table is built

Gamma Correction

Power-law mapping, normalised to \([0,1]\):

\[ g = c\, f^{\gamma} \]

  • \(\gamma < 1\): brightens shadows, compresses highlights (common for dark/backlit scenes)
  • \(\gamma > 1\): darkens — used to encode images for display (monitors expect roughly \(\gamma \approx 2.2\) decoding, so cameras/encoders pre-apply \(\gamma \approx 1/2.2\))
  • \(\gamma = 1\): identity
def gamma_lut(gamma):
    inv = 1.0 / gamma
    table = ((np.arange(256) / 255.0) ** inv * 255).astype(np.uint8)
    return table

bright = cv2.LUT(img, gamma_lut(0.5))   # gamma < 1 -> brighter shadows

The Log Transform

\[ g = c \log(1 + f) \]

  • Compresses a very wide dynamic range (e.g. Fourier-spectrum magnitude, HDR radiance) into a displayable range
  • Expands dark values, compresses bright ones — the opposite shape to \(\gamma > 1\)
  • Constant \(c\) is usually chosen so the maximum input maps to 255: \(c = 255 / \log(1+f_{\max})\)
  • Classic use: visualising a DFT magnitude spectrum (see Lecture 5)

Contrast Stretching

Piecewise-linear mapping that expands a narrow intensity band to fill the full range:

\[ g = \frac{f - f_{\min}}{f_{\max} - f_{\min}} \times 255 \]

  • Simple min–max normalisation; sensitive to outliers (one hot pixel ruins the stretch)
  • Robust variant: clip to the 1st/99th percentile before stretching
  • OpenCV: cv2.normalize(img, None, 0, 255, cv2.NORM_MINMAX)
  • Piecewise-linear generalisation ("contrast stretching" in G&W): pick control points \((r_1,s_1), (r_2,s_2)\) and interpolate linearly between them — lets you boost a mid-tone band without clipping

The Histogram

The histogram \(h(k)\) counts how many pixels take intensity \(k\); the normalised histogram is a probability mass function:

\[ p(k) = \frac{h(k)}{MN}, \qquad k = 0,\dots,255 \]

  • A narrow, off-centre histogram → low-contrast image
  • A histogram with two separated modes → a foreground/background pair (useful for thresholding, later this lecture)
hist = cv2.calcHist([gray], [0], None, [256], [0, 256])

Histogram Equalisation

Goal: redistribute intensities so the output histogram is approximately uniform → maximises global contrast.

The mapping is the (scaled) cumulative distribution function (CDF) of the input:

\[ T(k) = 255 \sum_{j=0}^{k} p(j) = 255 \cdot \text{CDF}(k) \]

  1. Compute the histogram \(h(k)\)
  2. Compute the CDF and scale it to \([0,255]\) — this is the LUT
  3. Apply the LUT to every pixel
eq = cv2.equalizeHist(gray)   # grayscale only

Pitfall: on colour images, equalising R, G, B independently shifts the hue. Equalise the luminance channel instead (e.g. Y in YCbCr, or V in HSV) and recombine.

Histogram Matching (Specification)

Generalises equalisation: instead of a uniform target, match a reference histogram (e.g. from a well-exposed reference frame).

  1. Compute the CDF of the source image, \(\text{CDF}_f\)
  2. Compute the CDF of the reference/target histogram, \(\text{CDF}_z\)
  3. For each source level \(k\), find \(z\) such that \(\text{CDF}_z(z) \approx \text{CDF}_f(k)\) — this defines the mapping \(k \mapsto z\)

Useful for colour/exposure consistency across a video sequence or a multi-camera rig — match every frame's histogram to a reference frame so downstream thresholds behave consistently.

CLAHE — Contrast-Limited Adaptive Histogram Equalisation

Plain equalisation is global: one bright region can dominate and wash out detail elsewhere. CLAHE equalises locally, with a clip limit to control noise amplification.

  1. Split the image into a grid of tiles (e.g. 8×8)
  2. Compute a histogram per tile; clip bins above a threshold and redistribute the clipped mass (this is the "contrast-limited" part — prevents flat regions from over-amplifying sensor noise)
  3. Equalise each tile independently
  4. Bilinearly interpolate the tile boundaries to avoid blocking artefacts
clahe = cv2.createCLAHE(clipLimit=2.0, tileGridSize=(8, 8))
enhanced = clahe.apply(gray)

Practitioner note: CLAHE on the L channel of Lab colour space is the standard recipe for uneven-lighting scenes (shadows, backlighting) on the Pi camera.

Practitioner Notes — Point Operations

  • Integer overflow: plain img + 50 in NumPy wraps around (uint8 mod 256); use cv2.add / cv2.convertScaleAbs, which saturate at 0/255
  • Colour equalisation: never equalise R, G, B independently — work in a luma/chroma space
  • Gamma vs. exposure: gamma correction cannot recover detail that was clipped (over/under-exposed) at capture — fix exposure/gain first, correct tone second
  • CLAHE tile size: too small → noise amplification and blocking; too large → degenerates toward global equalisation. Start at 8×8 and tune per scene
  • All of these are \(O(N)\) per pixel — cheap enough to run every frame on the Raspberry Pi 5 CPU

Thresholding: Turning Intensity into a Decision

The simplest segmentation operator — a point operation whose output is binary:

\[ g(x,y) = \begin{cases} 255 & f(x,y) \ge T \\ 0 & f(x,y) < T \end{cases} \]

  • Works well when foreground and background occupy separated intensity ranges (bimodal histogram)
  • The entire question is: how do we choose \(T\)? — fixed, global-optimal, or spatially varying

Otsu’s Method — Optimal Global Threshold

Chooses \(T\) automatically by treating the histogram as two classes (background/foreground) and picking the split that maximises between-class variance \(\sigma_B^2(T)\) (equivalently minimises within-class variance):

\[ \sigma_B^2(T) = \omega_0(T)\,\omega_1(T)\,\big[\mu_0(T) - \mu_1(T)\big]^2 \]

  • \(\omega_0, \omega_1\) — class probabilities (fraction of pixels below/above \(T\))
  • \(\mu_0, \mu_1\) — class means
  • Exhaustive search over all 256 candidate thresholds — cheap, exact, no parameters to tune
  • Assumes a roughly bimodal histogram; degrades on scenes with uneven illumination or three-or-more intensity classes
_, th = cv2.threshold(blurred, 0, 255, cv2.THRESH_BINARY + cv2.THRESH_OTSU)

Adaptive Thresholding

Instead of one global \(T\), compute a local threshold per pixel from its neighbourhood:

\[ T(x,y) = \text{mean or Gaussian-weighted mean of the } b\times b \text{ window around } (x,y) \; - \; C \]

  • Robust to gradual illumination gradients that break Otsu (a spotlight, a shadow gradient across the frame)
  • Two flavours in OpenCV: ADAPTIVE_THRESH_MEAN_C and ADAPTIVE_THRESH_GAUSSIAN_C
  • Two knobs to tune: block size \(b\) (must be odd; too small → noisy, too large → behaves like global) and the constant \(C\) subtracted from the local mean
th = cv2.adaptiveThreshold(blurred, 255, cv2.ADAPTIVE_THRESH_GAUSSIAN_C,
                            cv2.THRESH_BINARY, 21, 5)   # block=21, C=5

Sauvola Thresholding

A refinement of adaptive mean thresholding, designed originally for document/text binarisation under uneven lighting:

\[ T(x,y) = m(x,y)\left[1 + k\left(\frac{s(x,y)}{R} - 1\right)\right] \]

  • \(m(x,y)\), \(s(x,y)\) — local mean and standard deviation in a window
  • \(R\) — dynamic range of the standard deviation (typically 128 for 8-bit), \(k\) — a tunable weight (typically 0.2–0.5)
  • In low-variance (flat) regions, \(T\) drops toward \(m(1-k)\), suppressing background noise that plain adaptive thresholding would misclassify
  • Not built into core OpenCV — implement via integral images for mean and mean-of-squares (fast, \(O(1)\) per pixel after the integral image is built), or use scikit-image’s threshold_sauvola

Choosing a Thresholding Method

Method Best for Cost Weakness
Global (fixed \(T\))Controlled, repeatable lightingO(1)Breaks the moment lighting changes
OtsuBimodal histogram, uniform lightingO(256)One threshold for the whole frame
Adaptive (mean/Gaussian)Gradual illumination gradientsO(N) w/ box filterTwo parameters to tune per scene
SauvolaText/fine structure, strong local contrastO(N) w/ integral imagesMore parameters; tuned for document images

Rule of thumb for the Pi 5 labs: start with Otsu; switch to adaptive/Sauvola the moment you see a shadow or gradient across the frame.

Image Arithmetic

Pixel-wise operations between two (same-size) images:

  • Addition/subtraction: cv2.add, cv2.subtract — saturating (clip to [0,255]), unlike raw NumPy +/- which wraps
  • Weighted sum (blending): \(g = \alpha f_1 + (1-\alpha) f_2\) via cv2.addWeighted(f1, alpha, f2, 1-alpha, 0)
  • Absolute difference: cv2.absdiff(f1, f2) — the workhorse of frame differencing (below) and change detection

Alpha Compositing

Overlay a foreground image/graphic onto a background using a per-pixel opacity map \(\alpha(x,y) \in [0,1]\) (the alpha channel):

\[ g(x,y) = \alpha(x,y)\, f_{\text{fg}}(x,y) + \big(1-\alpha(x,y)\big)\, f_{\text{bg}}(x,y) \]

  • Used for HUD overlays (bounding boxes, masks, heatmaps) that should blend rather than fully occlude the frame
  • In OpenCV: build a float mask, broadcast-multiply, sum — or pack a 4th (BGRA) channel and composite manually

Bitwise Operations & Masks

  • cv2.bitwise_and, _or, _xor, _not — operate per bit/per pixel, typically with a binary mask as one operand
  • Classic pattern: mask out a region of interest, or combine two binary masks (e.g. a colour mask AND a motion mask)
masked = cv2.bitwise_and(frame, frame, mask=binary_mask)  # keep frame only where mask!=0
combined = cv2.bitwise_and(color_mask, motion_mask)        # AND two conditions

This is exactly how Lab 4’s HSV colour detector isolates a coloured object: threshold in HSV to get a mask, then bitwise_and it against the original frame.

Frame Differencing — the Simplest Motion Detector

  1. Keep a reference/background frame \(B\) (the previous frame, or a running average)
  2. Compute \(D = |I_t - B|\) via cv2.absdiff
  3. Threshold \(D\) (Otsu or a fixed value) to get a binary motion mask
  4. Clean the mask with morphology (Lecture 6) and find contours (Lecture 5 lab) to localise moving objects
diff = cv2.absdiff(gray_prev, gray_curr)
_, motion_mask = cv2.threshold(diff, 25, 255, cv2.THRESH_BINARY)

Limitation: sensitive to camera shake and lighting flicker; only detects the edges of a uniformly-coloured moving object (its interior looks unchanged). Background subtraction (MOG2/KNN, Lecture 11) fixes both.

Code Walkthrough — 01_opencv_basics.py

This week’s reference script (in the course repository) exercises exactly these operations end to end:

def adjust_brightness_contrast(img, alpha=1.2, beta=20):
    """alpha = contrast gain, beta = brightness offset. Safe (saturating)."""
    return cv2.convertScaleAbs(img, alpha=alpha, beta=beta)

img = cv2.imread(args.image)            # NOTE: OpenCV loads as BGR, not RGB
gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
hsv  = cv2.cvtColor(img, cv2.COLOR_BGR2HSV)
annotated = adjust_brightness_contrast(img.copy(), alpha=1.15, beta=15)
  • cv2.convertScaleAbs(img, alpha, beta) computes \(g = \text{saturate}(\alpha f + \beta)\) — a linear point operation, safely clipped
  • Note the BGR-not-RGB gotcha: OpenCV’s native channel order trips up almost everyone the first time

Practitioner Notes — Arithmetic & Masks

  • Never subtract uint8 arrays with raw NumPy when the result can go negative — it wraps (e.g. \(5 - 10 = 251\)). Cast to int16/float32 first, or use cv2.subtract/cv2.absdiff
  • Masks must match the operand’s size and be single-channel uint8; a common bug is passing a 3-channel mask
  • addWeighted assumes both inputs are the same dtype/size — resize/crop to match before blending
  • On the Raspberry Pi 5, all of today’s operations are vectorised NumPy/OpenCV calls — they run comfortably at full camera frame rate; the bottleneck is almost always capture I/O, not this arithmetic

Key Takeaways

  • Point operations map \(f(x,y) \to g(x,y)\) independently per pixel — build them once as a LUT, apply in \(O(1)\)
  • Histogram equalisation/CLAHE fix contrast; gamma/log fix tone; know which problem you actually have
  • Thresholding turns intensity into a decision — Otsu for uniform lighting, adaptive/Sauvola when lighting varies across the frame
  • Saturating arithmetic (cv2.add/subtract/absdiff) avoids silent wraparound bugs that raw NumPy will happily produce
  • Frame differencing is the simplest motion cue — good enough for Lab 5, replaced by background subtraction once we need robustness (Lecture 11)
